# Physical Backbone layout and live port configuration

Topology owns the immutable board layout, generated from the `spaghettilab,physical-backbone` Devicetree node. Port owns the four user signal modes. Field Update copies the descriptor from each CAN peer; GET_STATUS includes these copies at connection and on presence refresh. Older peers have no descriptor and must not be assigned an invented layout.

Layout 1 has two module positions: Connector (one six-pin port) and Function (two six-pin ports). Function port 1 mirrors Connector port 1. Function port 2 has fixed 5V/GND at pins 1/6 and four MCU signals at pins 2..5, backed by the DTS-selected Port. The CAN network port is never exposed as a user module port.

Descriptor V1 is 13 bytes: version, MCU (1 S3, 2 C3), NFC antennas, layout, backend port, capability low/high, four signal modes, I2C speed (0 standard, 1 fast), source (0 idle, 1 manual, 2 NFC). Modes: 0 disconnected, 1 input, 2 low output, 3 high output, 4 SDA, 5 SCL; bits 4/5 select pull up/down for input. Reserved modes are rejected. CAN descriptors use three indexed fragments of six bytes, published only when all fragments arrive in order.

Operation 32 accepts node ID, a four-byte signal map, speed and a 20-byte expected NFC snapshot (registry/vendor/type, UID length, ten UID bytes, automatic flag). It responds only after the selected microcontroller has applied and persisted the map. CAN applies stage four snapshot fragments before the map, require a matching transaction and expire after two seconds; acknowledgment is bounded at 800ms. Presence sweeps and firmware transfers serialize with this operation. Broadcast writes and changed tags are rejected. Runtime Module owners block direct reconfiguration. Unsupported muxes are rejected before changing pins.

The CRC-protected settings record retains a manual pin map and up to sixteen NFC electrical associations on each Backbone. Storage failure restores the previous map. NFC refresh restores learned associations after reboot, locks manual edits for recognized definitions and disconnects an automatic map when its module disappears. The project retains names, drafts and full catalog metadata. Matching requires registry, vendor and module type; generic NFC tags without these fields remain unknown. The shared catalog currently has two demo records without electrical pinouts, so neither receives fabricated pin assignments.

The existing board backend supports I2C at its fixed SDA/SCL pins and independent GPIO. It must not claim SPI/UART/PWM/ADC support absent a configured board backend. Catalog-driven application uses the same runtime validation as manual application. Custom protocol field definitions remain project authoring data; the existing Device Profiles workflow installs executable profiles. Verification covers descriptor codecs, unknown versions, pin constraints, board selection, NFC lookup, persistence, rollback and real firmware compilation; hardware qualification requires readback and an electrical measurement after flashing.
